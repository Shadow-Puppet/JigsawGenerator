Create the Rust side of the build pipeline:

1. **Root Cargo.toml** — Workspace with members `crates/puzzle-core` and `crates/puzzle-wasm`. Use `resolver = "2"`.

2. **.gitignore** — Add `/target/`, `crates/puzzle-wasm/pkg/`, `web/node_modules/`, `web/dist/`. Keep it comprehensive for a Rust + Node hybrid project.

3. **crates/puzzle-core/** — Pure Rust library (NO wasm-bindgen dependency):
   - `Cargo.toml`: name `puzzle-core`, edition `2024`, depends on `serde = { version = "1.0", features = ["derive"] }`
   - `src/lib.rs`: Implement:
     - `GridConfig` struct with `rows: u32, cols: u32` (derive Serialize, Deserialize, Debug)
     - `PieceBreakdown` struct with `total, corners, edges, interior: u32` (derive Serialize, Deserialize, Debug)
     - `compute_piece_breakdown(config: &GridConfig) -> Result<PieceBreakdown, String>` — validates rows/cols > 0, computes correct breakdown including edge cases (1x1, 1xN, Nx1, 2x2)
     - Unit tests: test 3x4 grid (12 total, 4 corners, 6 edges, 2 interior), 1x1 grid (1 total, 1 corner, 0 edges, 0 interior), 1x5 grid (5 total, 2 corners, 3 edges, 0 interior), 2x2 grid (4 total, 4 corners, 0 edges, 0 interior), invalid 0 rows, invalid 0 cols

4. **crates/puzzle-wasm/** — Thin WASM bindings wrapping puzzle-core:
   - `Cargo.toml`: name `puzzle-wasm`, edition `2024`, `crate-type = ["cdylib", "rlib"]`, depends on `wasm-bindgen = "0.2"`, `serde_json = "1.0"`, `console_error_panic_hook = "0.1"`, `puzzle-core = { path = "../puzzle-core" }`. Add `[package.metadata.wasm-pack.profile.release] wasm-opt = ['-Os']`.
   - `src/lib.rs`: Implement:
     - `init_panic_hook()` — calls `console_error_panic_hook::set_once()`
     - `compute_pieces(config_json: &str) -> String` — deserializes JSON to GridConfig, calls `puzzle_core::compute_piece_breakdown`, serializes result or error back to JSON string. Both `#[wasm_bindgen]` exported.

5. **Verify Rust builds:**
   - Run `cargo test` from workspace root — all puzzle-core tests must pass
   - Run `cargo check` — no warnings or errors

6. **Build WASM:**
   - Ensure `wasm-pack` and `rust-wasm` (wasm32-unknown-unknown target) are available. If `wasm-pack` is not found, check if it can be installed from the system package manager or cargo install. Do NOT use sudo.
   - Run `wasm-pack build crates/puzzle-wasm --target web --dev` from project root
   - Verify `crates/puzzle-wasm/pkg/` is generated with `.wasm`, `.js`, and `.d.ts` files

Create the web side and wire up the WASM round-trip:

1. **web/package.json:**
   - name: `puzzle-generator-web`, private: true, type: `module`
   - Scripts:
     - `dev:wasm`: `wasm-pack build ../crates/puzzle-wasm --target web --dev` (fast debug WASM build)
     - `build:wasm`: `wasm-pack build ../crates/puzzle-wasm --target web --release` (optimized WASM build)
     - `dev`: `vite` (Vite dev server, assumes WASM already built)
     - `build`: `npm run build:wasm && vite build` (full production build)
     - `preview`: `vite preview`
   - devDependencies: `typescript`, `vite`, `vite-plugin-wasm`

2. **Run `npm install`** from web/ directory to install dependencies.

3. **web/tsconfig.json:**
   - target: `ESNext`, module: `ESNext`, moduleResolution: `bundler`
   - strict: true, noEmit: true
   - include: `["src"]`

4. **web/vite.config.ts:**
   - Import and use `vite-plugin-wasm` plugin
   - Set `build.target: 'esnext'`
   - If relative import path `../../crates/puzzle-wasm/pkg` causes Vite resolution issues, add a resolve alias mapping `puzzle-wasm` to the pkg directory. Try without alias first.

5. **web/index.html:**
   - Standard HTML5 boilerplate, charset utf-8, viewport meta
   - Title: "Puzzle Pattern Generator"
   - Body structure:
     - `<div id="loading">Loading WASM module...</div>` (visible initially)
     - `<div id="app" style="display:none">` (hidden until WASM loads):
       - Heading: "Puzzle Pattern Generator"
       - Subheading or description: brief text about computing piece breakdown
       - Form with: label + number input for Rows (id="rows", default 3, min 1), label + number input for Columns (id="cols", default 4, min 1), Compute button (id="compute")
       - Result area `<div id="result"></div>` for displaying output
   - Script tag: `<script type="module" src="/src/main.ts"></script>`

6. **web/src/style.css:**
   - Minimal but presentable styling per user decision
   - Centered layout (max-width container, margin auto)
   - Basic typography (system font stack, reasonable sizes)
   - Input and button styling (padding, border, readable)
   - Error state class (`.error` — red text)
   - Result area styling (background, padding, border-radius)
   - NOT ugly but NOT designed — functional and clean

7. **web/src/main.ts:**
   - Import `init`, `compute_pieces`, `init_panic_hook` from wasm-pack pkg output. Use relative path `../../crates/puzzle-wasm/pkg` (this imports the generated ESM from `--target web`).
   - Import `./style.css`
   - Define TypeScript interfaces: `PieceBreakdown` (total, corners, edges, interior as numbers), `ErrorResponse` (error as string), union type `ComputeResult`
   - Type guard: `isError(result): result is ErrorResponse`
   - `main()` async function:
     - Get loading and app elements
     - `await init()` then `init_panic_hook()` — on success hide loading, show app
     - On failure: set loading text to error message, console.error
     - Wire compute button click handler:
       - Read rows/cols from inputs, parseInt with radix 10
       - Call `compute_pieces(JSON.stringify({ rows, cols }))`
       - Parse JSON response
       - If error: display error message with `.error` class
       - If success: display piece breakdown (total, corners, edges, interior) in result div
   - Call `main()`

8. **End-to-end verification:**
   - From web/ directory: run `npm run dev:wasm` to build WASM (debug)
   - Run `npm run build` for full production build
   - Check that dist/ directory is produced with bundled .wasm
