**Cargo.toml** — Add dependencies to puzzle-core:
```toml
kurbo = { version = "0.13", features = ["serde"] }
rand = { version = "0.10", default-features = false }
```

Note: `rand` with `default-features = false` avoids pulling `getrandom` which panics on wasm32-unknown-unknown. We only need `SeedableRng` and `Rng` traits.

**config.rs** — Create with these types (all derive Serialize, Deserialize, Debug, Clone):

1. `Unit` enum — `Millimeters`, `Inches`. Methods: `to_mm(value: f64) -> f64` (Inches: value * 25.4), `from_mm(value_mm: f64) -> f64` (Inches: value_mm / 25.4).

2. `PuzzleConfig` — The top-level configuration combining everything:
   - `rows: u32` — grid rows (validated: 2..=100)
   - `cols: u32` — grid columns (validated: 2..=100)
   - `width: f64` — puzzle width in mm (after conversion)
   - `height: f64` — puzzle height in mm (after conversion)
   - `unit: Unit` — display/input unit
   - `tab: TabConfig`
   - `jitter: JitterConfig`
   - `border: BorderConfig`
   - `seed: String` — user seed string (empty = auto-generate)
   - Implement `Default` with: rows=6, cols=8, width=297.0, height=210.0, unit=Millimeters, defaults for sub-configs, seed=""

3. `TabConfig` — `size_pct: f64` (fraction 0.15..=0.45, default 0.25). Validation method.

4. `JitterConfig` — `amount: f64` (fraction 0.0..=1.0, default 0.5). Validation method.

5. `BorderConfig` — `corner_radius: f64` (mm, 0.0..=10.0, default 2.0). Validation method.

6. `PuzzleConfig::validate(&self) -> Result<(), String>` — Checks all bounds, returns first error found.

7. `PuzzleConfig::from_input(rows, cols, width, height, unit, ...) -> Result<PuzzleConfig, String>` — Constructor that converts units to mm and validates. When unit=Inches, multiply width/height by 25.4 before storing.

**seed.rs** — Create with:

1. `hash_seed(s: &str) -> u64` — FNV-1a hash (offset basis: 0xcbf29ce484222325, prime: 0x100000001b3). Iterate bytes, XOR then multiply. CRITICAL: Do NOT use std::hash::DefaultHasher — it is NOT portable across Rust versions.

2. `create_rng(seed_string: &str) -> ChaCha8Rng` — Hash string to u64, call `ChaCha8Rng::seed_from_u64(hash)`. Uses `rand::SeedableRng` and `rand_chacha::ChaCha8Rng`.

3. Unit tests:
   - `hash_seed("birthday")` returns same value on every run
   - `hash_seed("birthday") != hash_seed("christmas")`
   - `hash_seed("")` returns the FNV offset basis
   - `create_rng("test")` produces deterministic sequence: generate 3 `random_bool(0.5)` values, assert exact sequence
   - Two `create_rng("test")` instances produce identical sequences

**edge.rs** — Create with these types (all derive Serialize, Deserialize, Debug, Clone where appropriate):

1. `TabDirection` enum — `In`, `Out`. Derive Copy. Used for internal edges' tab direction.

2. `Edge` struct:
   - `start: kurbo::Point` — start coordinate in mm
   - `end: kurbo::Point` — end coordinate in mm
   - `is_border: bool` — true for edges on puzzle boundary
   - `direction: TabDirection` — In or Out (meaningless for borders, default to In)
   - `connector: Option<Vec<kurbo::CubicBez>>` — None until connector generation (Phase 3). Populated by ConnectorGenerator.

3. `EdgeParams` struct — Parameters passed to ConnectorGenerator:
   - `length: f64` — edge length in mm
   - `direction: TabDirection` — In or Out
   - `tab_size: f64` — tab size as fraction (0.15..=0.45)
   - `jitter_amount: f64` — jitter as fraction (0.0..=1.0)

4. `Edge::length(&self) -> f64` — Compute Euclidean distance between start and end using kurbo Point arithmetic: `(self.end - self.start).hypot()`.

**connector.rs** — Create with:

1. `ConnectorGenerator` trait:
   ```rust
   pub trait ConnectorGenerator: Send + Sync {
       /// Generate bezier curves for an edge connector.
       /// Returns control points in edge-local coordinates
       /// (0,0 = edge start, (length, 0) = edge end).
       fn generate(&self, params: &EdgeParams, rng: &mut ChaCha8Rng) -> Vec<kurbo::CubicBez>;

       /// Validate that generated curves stay within acceptable bounds.
       /// Default: check bounding box doesn't exceed 5% beyond nominal piece boundary.
       fn validate(&self, curves: &[kurbo::CubicBez], params: &EdgeParams) -> Result<(), String>;
   }
   ```
   Note: `rng` passed as param so the trait doesn't need to own RNG state — the grid controls the RNG sequence for determinism. Per CONTEXT.md, trait handles internal edges only; border edges handled separately.

2. `NullConnector` struct — Minimal implementation for testing. `generate()` returns empty Vec, `validate()` always returns Ok. This lets Plan 02 (grid engine) test without needing real connector shapes.
